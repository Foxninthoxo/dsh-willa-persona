# 教训

踩过的坑，通用化之后放在这里，跟包一起发布。规矩：只写现象、原因、改法，不写谁家账号、群号、本机路径、端口、密钥。新的写在最上面。

## A. 脚本存盘不带 BOM，5.1 会把中文当乱码，还能吞掉引号

**现象**：一个含中文的 `.ps1`，在新版 PowerShell 里跑得好好的，用系统自带的 Windows PowerShell 一跑就报「字符串缺少终止符」，行号还落在某句中文注释后面。

**原因**：Windows PowerShell 5.1 对**没有 BOM 的 UTF-8 文件**按系统本地编码（简体中文机器上是 GBK）解码。中文是多字节，某些字节序列会把后面的引号当成自己的尾巴吃掉，于是字符串永远不闭合。

**改法**：所有要交给 `powershell.exe` 跑的脚本，存盘时带 UTF-8 BOM；改完用 5.1 自己解析一遍（`[System.Management.Automation.Language.Parser]::ParseFile`）再执行。新版 PowerShell 默认 UTF-8，验不出来，别拿它当证据。

## B. 递归扫目录别用一把梭，先跳黑名单再进去

**现象**：遍历整个目录树的脚本偶尔整体失败，报「找不到路径的一部分」，而那个路径看起来根本不该被扫（测试残留的临时目录、失效的链接）。

**原因**：`递归 + 过滤` 是「先走进去、再筛掉」。目录里只要有一个指向已消失目标的链接，递归过程本身就会抛错，`忽略错误` 参数挡不住这种走进去就炸的情况。

**改法**：先列顶层目录、按黑名单筛掉不要的，再逐个进去递归。不想碰的目录从一开始就不进去，比事后忽略错误可靠。

## 0. 工具跑不动，先问是不是越界

**现象**：命令行明明装了某个程序，一跑就是 `Access is denied`，看起来像程序坏了或者路径错了。

**原因**：限制常常来自执行环境，不是工具本身——程序装在受限目录之外，或者子进程跑在更窄的权限下，都是「没装坏但不让跑」。同一个程序在主会话能跑、派出去的子任务跑不了，也是这个原因。

**改法**：先分清是「工具不行」还是「这一层不让」，再决定是提权、换个位置跑，还是换个更轻的替代方案（比如本来要抽帧，先拿现成的缩略图顶上）。别在「权限」上反复试同一个命令。

## 1. 上下文不是被「聊」满的，是被「贴」满的

**现象**：越聊越慢，一轮里工具稍微多一点就超时。

**原因**：把子任务的大段输出整篇贴回主对话；会话记录涨到几 MB 之后，每一轮都要把全部历史重新过一遍。慢是结构性的，不是偶发。

**改法**：子任务只回结论摘要（一两句），全文落盘，要用的时候再按需检索；会话记录涨到 3 MB 左右就开新会话，换之前先把交接写好。

## 2. 自省不要变成待办

**现象**：发现毛病，记一条待办，然后就没有然后了。

**原因**：待办只解决「接下来要做」，不解决「下次别再犯」。

**改法**：自省出的每一处错当场写成一条教训入库（写清错在哪、以后怎么改）；待办只放还没做完的活。教训要通用、脱敏，才能随包发布。

## 3. 受限环境里别去判断「服务死了没有」

**现象**：子任务看不到端口在听，就断定服务挂了，重启一下，把正在跑的会话和任务一起带走。

**原因**：沙箱里进程和端口看不全，看不到不等于没有。

**改法**：判断活动只看日志有没有还在长；重启这类动作交给人决定，别让子任务自己动。

## 4. 别凭感觉说「卡了」「没变」

**现象**：说「好像卡了」「应该没变」，回头被数据打脸。

**原因**：感觉不是证据。

**改法**：量出来再说——多大、多久、几个、几毫秒。量不了就直说量不了。

## 5. 长活先记账再动手

**现象**：活干到一半上下文断了，回来不知道干到哪。

**原因**：进度只存在对话里。

**改法**：开长活之前先写一句「在做什么、悬着什么、下一步」，干完再补一句结果。
